# LTA チーム管理(レゼルテニスアカデミー)

監督が選手の育成・管理に使う、チーム全員が見られる画面です。ビルドなしの HTML/JS(`web/`)と、Supabase(データベース・ログイン・ファイル保存)でできています。
コート検索(リポジトリの他の部分)とは独立しているので、新しいリポジトリへ `team/` ごと移せます。

見た目の見本(サンプルデータ・保存なし)は、Claude のページ機能で作ってあります。

## できること

| 場所 | 中身 | 見られる人 | 書ける人 |
|---|---|---|---|
| ホーム | お知らせ・戦績・次の予定(出欠)・最近の試合・ミーティング・ニュース。監督には「確認が必要なこと」 | 全員 | — |
| 試合 | 日付・選手・相手・大会・スコア・勝敗・メモ・写真 | 全員 | 監督 |
| 選手 | プロフィール・アイコン写真(本人が選ぶ)・ランク・チーム | 全員 | 本人(ランク・チーム・役割は監督) |
| ランク | S/A/B と順位(上位3人は表彰台) | 全員 | 監督 |
| お知らせ | 監督 → 宛先のチーム。開くと自動で既読。監督は未読の人が分かる | 宛先のチームの選手と監督 | 監督 |
| 予定 | 練習・大会。「対象のチーム」は出欠の対象(予定は全員に見える)。出欠の回答 | 予定は全員。出欠は同じチームと監督 | 監督(出欠は本人) |
| ニュース・動画 | 選手が共有 → 監督が承認してから全員に見える | 承認後は全員。承認前は本人と監督 | 選手(承認は監督) |
| テニスノート | 気づき・反省 | 本人と監督だけ | 本人 |
| 目標 | 月の目標とふりかえり。監督がコメント | 本人と監督だけ | 本人(コメントは監督) |
| ミーティング | 議事録と決まったこと | 全員 | 監督と記録係 |
| テスト | 画面で解答して自動採点。ルール(簡単)とシチュエーション(難しい)。結果は全員に見える | 全員 | 問題は監督 |

退部した選手は、ログインを止めます。記録は残り、監督は見られます。他の選手には名前が出ません。

## 決まっていないこと・あとで検討

- 今日の一問(毎日1問を出して、連続日数を競う): いったんなし
- 試合の動画をアップロードして分析する機能
- ニュース・試合情報の自動取得(まずは手入力)
- 画面からの相談窓口(相談はこれまでどおり LINE)
- ホーム画面に追加したときのアイコン(LTA のロゴ)

## 設置の手順(最初の1回)

1. https://supabase.com で、無料のプロジェクトを作る。
2. SQL Editor に `supabase/schema.sql` を貼って実行する(何度実行してもよい)。
3. Authentication → Sign In / Providers → Email で **「Allow new users to sign up」を OFF** にする(外の人が自分で登録できないように)。選手の追加は、監督の画面からサーバー側の処理で行うので、OFF のままで動きます。
4. Authentication → Users → Add user で、**監督のメールアドレス**を登録する(「Auto Confirm User」を ON)。
5. SQL Editor で、監督にする:
   `update profiles set role = 'coach', name = '山田 監督' where id = (select id from auth.users where email = '監督のメール');`
6. サーバー側の処理(Edge Functions)を置く。Supabase CLI を入れて:
   ```bash
   supabase login
   supabase link --project-ref <プロジェクトのID>
   supabase secrets set CODE_PEPPER=$(openssl rand -hex 32)
   supabase functions deploy player-admin
   supabase functions deploy code-login
   ```
   `CODE_PEPPER` は、個人コードをハッシュにするときに混ぜる秘密です。**どこにも書き写さず**、Supabase の中だけに置いてください(変えると、発行済みのコードが全部使えなくなります)。
7. Authentication → URL Configuration の Site URL に、公開するページの URL を入れる(監督のログインメールのリンク先)。
8. `web/config.js` に Project URL と anon キーを入れる(**service_role キーは絶対に入れない**)。
9. `web/` を GitHub Pages か Cloudflare Pages で公開する。

### 使い始め

1. 監督は、公開したページで「監督はこちら(メールでログイン)」から入る。
2. 「選手」タブの「選手を追加」で名前を入れると、コードが1回だけ表示される。LINE で**本人だけ**に渡す。
3. 選手は、コードを入れるだけ。1回入れると、そのスマホが覚える。
4. コードを無くした・漏れた → 選手の「編集」から「コードを再発行」(前のコードは使えなくなる)。
5. 退部 → 選手の「編集」から「退部にする」。

## 守りの考え方

- **データを守っているのは `schema.sql` の行レベル制限(RLS)**です。画面の隠しボタンではなく、データベース側で止めます。
- 個人コードは8文字(31種類の文字、約8.5兆通り)。保存するのは**ハッシュだけ**で、同じ接続元から10分に10回までしか試せません。
- ログイン後の情報(セッション)は、スマホに保存されます。退部にすると、新しくは入れなくなり、すでに入っているスマホも、しばらくすると使えなくなります。
- 添付ファイルは非公開の保存場所に置き、見るたびに1時間だけ有効なリンクを作ります。
- 中学生の写真・名前・成績が入ります。**保護者への説明と同意は、運営側で必ず取ってください**(アイコン写真は本人が選ぶ形ですが、顔写真を載せる場合は特に)。
- 既知の限界: テストの採点は画面で行うので、問題を読める選手が点数を偽ることは、技術的には可能です(監督は結果を消せます)。

## 確かめたこと・まだ確かめていないこと

確かめたこと:
- `supabase/tests/rls.test.mjs`: 権限65項目。Supabase の土台を再現した PostgreSQL 互換のデータベースで `schema.sql` を動かし、「だれが何を見られる・書けるか」を確かめます(2回実行しても壊れないことも)。
- 個人コードの作り方(偏りなし・紛らわしい文字なし・重複なし)とハッシュ化は、動かして確かめました。
- 画面は、iPhone SE と iPhone 13、ライトとダークで、見本を使って確かめました。

**まだ確かめていないこと(設置のときに、必ず試してください)**:
- 本物の Supabase との接続(ログイン・保存・画像のアップロード)。
- `code-login` の中の、ログイン情報への交換(`generateLink` → `verifyOtp`)。Supabase のバージョンによって細部が変わることがあります。
- 退部にしたあと、すでにログインしているスマホが実際に入れなくなるまでの時間。

設置後の確認(5分): ①監督で選手を追加 → ②別のスマホでコードを入れて入れる → ③間違ったコードは入れない → ④「退部にする」→ そのコードが使えなくなる。
