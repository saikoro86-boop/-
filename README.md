# puppeteer-form-automation

Puppeteer (stealth) + TypeScript によるフォーム自動化のボイラープレートと、SNS 投稿を「下書き → 承認 → 予約投稿」で管理する AI 社員(`npm run sns`)です。

## セットアップ

```bash
npm install
cp .env.example .env   # 値を入れる(.env は .gitignore 済み。コミットしないこと)
npm run typecheck
```

## 1. フォーム自動化

```bash
npm start
```

- `.env` の `TARGET_URL` を開き、`LOGIN_ID` / `LOGIN_PASSWORD` でログインします。
- フォームのセレクタは `src/index.ts` の `SELECTORS` を対象サイトに合わせて書き換えてください。
- セッション情報は `USER_DATA_DIR`(既定 `./user_data`)に保持されます。

## 2. SNS 管理 AI 社員

Claude が投稿文を下書きし、人が承認したものだけを X / Threads / Instagram に投稿します。

### 事前準備

- `.env` に `ANTHROPIC_API_KEY` と、使う媒体の認証情報を設定します(`.env.example` 参照)。
- `config/brand.md` に自社のトーンや禁止事項を書くと、投稿文に反映されます。

### 使い方

```bash
# 下書きを作る(媒体は省略すると x,threads,instagram すべて)
npm run sns -- draft "10/10から秋の新メニュー販売開始" --image https://example.com/menu.jpg --at "2026-10-10T09:00+09:00" --platforms x,threads

npm run sns -- list [pending|approved|rejected|posted|failed]   # 一覧
npm run sns -- show <id>                                        # 1件表示
npm run sns -- edit <id> "<新しい本文>"                          # 編集(pending に戻る)
npm run sns -- approve <id> [<id> ...]                          # 承認
npm run sns -- reject <id> [<id> ...]                           # 却下
npm run sns -- publish [--dry-run]                              # 投稿時刻を過ぎた承認済みを投稿
```

### 流れ

1. `draft` で下書きを作る(`pending`)
2. 内容を確認し、`approve` で承認(`approved`)
3. `publish` を実行すると、予約時刻(`--at`)を過ぎた承認済みの下書きが投稿される(`posted`)
   - `--at` を付けなかった場合は、承認後の次回 `publish` ですぐ投稿されます。
   - `publish` は自動では動かないので、予約投稿として使うなら cron などで定期実行してください。
   - 失敗すると `failed` になり、原因は `show` で確認できます。直して `approve` し直すと再投稿されます。

### 注意点

- 文字数上限: X は 280(全角は 2 として換算)、Threads は 500 文字、Instagram は 2200 文字。超えると承認できません。
- Instagram は画像が必須です(`--image` に公開 URL を指定)。
- X への画像付き投稿は未対応です。
- 下書きは `drafts/` に保存されます(`.gitignore` 済み)。

## 3. テニスコート空き検索

奈良市・生駒市(「いつでも貸館」方式の予約サイト)のテニスコート空き状況をまとめて調べ、スマホ向けページに表示します。ログインは不要です。

```bash
npm run courts -- 2026-11-14 [市名]   # 指定日の空きをコマンドで確認
npm run courts:build                  # 今後30日分を public/data.json に出力
```

- `public/index.html` が画面です。`data.json` と同じ場所に置いて開きます(日付・エリア・時間帯で絞り込み)。
- 対象サイトは `config/courts.json` で追加できます。同じ「いつでも貸館」方式の市なら URL を足すだけです。
- `.github/workflows/courts.yml` が3時間ごとに取得し、**画面と `data.json` だけを、公開用の別リポジトリ**に書き出します(このリポジトリは非公開のまま、取得の仕組みを隠せます)。
  - 公開用リポジトリ: 新しく作って Public にし、Settings → Pages で「Deploy from a branch」→ `main` / `/(root)` を選びます。
  - このリポジトリの Settings → Secrets and variables → Actions に、Variables: `SITE_REPO`(公開用リポジトリ名、ownerなし)、Secrets: `SITE_REPO_TOKEN`(公開用リポジトリの Contents 書き込み権限だけを持つ fine-grained トークン)を登録します。
  - 公開される `data.json` には、取得元のURL・IDやエラー詳細は含めません。
- 空き状況の取得にはログインや予約操作を行いません。サーバに負荷をかけないよう、1リクエストごとに待ち時間を入れています。

### 奈良スーパーアプリ(県内の多数の施設を自動で拾う)
奈良スーパーアプリのゲスト画面が使っているデータを、`src/courts/narasuperapp.ts` で取得します。
- 施設一覧(`getTopInfo`)から、**利用目的に「テニス」を含む建物を全部自動で拾います**(2026-11 時点で35建物・29施設。「テニスで検索して出る施設は全部テニス」の方針)。設備名に「テニス」を含む建物は、そのコートだけ。体育館・競技場だけの建物(8施設)は、会議室・研修室・トレーニング室などを除いて、すべて表示し、「体育館・競技場など」と明記します。目的に「テニス」が付いていない建物は対象外です(確認した105建物のうち、設備名にコートを含むのは香芝市総合体育館のバドミントン等だけでした)。設備ごとの利用目的は、ゲストの画面には出ません(予約画面の「設備を絞り込む」は設備名だけ。利用目的は、ログイン後の予約入力で選ぶと思われます)。目的に「テニス」が付いた建物には、テニス用の設備が少なくとも1つあるので、部屋を除いた設備を、すべて出しています。取得は、一時的な通信エラーに備えて、最大3回やり直します。エリア名は市町村名(橿原市、天理市、宇陀市、葛城市、斑鳩町、三宅町、田原本町、広陵町、大和郡山市、明日香村、香芝市など)。
- ログイン・トークンは不要です。建物ごとに1回のPOSTで全日付分(今は2〜3週間)が返ります。低頻度(定期更新で建物ごとに1回、間に1.5秒の待ち)で使います。
- 「予約の明細がない枠 = 空き」と読んでいます。**大和郡山市総合公園は、公式の画面と一致することを確認済みです**(2026-11-06 時点で、11/21(土)はテニスコートB 12-13時、C/D/E 16-17時が空き、11/22(日)は空きなし)。ほかの施設は、同じ読み方を当てはめていて、個別の突き合わせはまだです。公式の空き状況と食い違う場合は教えてください。
- これらの施設は「照会のみ」(`isInquiryOnly`)で、予約自体は各施設の公式窓口で行います。
- 設定は `config/courts.json` の `type: "nsa-auto"`。手動で建物を指定する `type: "nsa"`(`targets` に `facilityId`/`buildingId`)も使えます。
- `npm run courts -- 2026-11-21 橿原` のように、市町村名で絞って確認できます。

### 「●」(空きだが、ネット予約は受付外)
「いつでも貸館」方式の予約サイトの凡例(奈良市の画面で確認)は、次のとおりです。
- **○ = 空き(インターネット予約受付中)**、**× = 予約済(インターネット予約受付中)**
- **● = 空き**(ネット予約の対象外。電話・窓口での予約)、**× = 予約済**、**- = 受付期間外**
- 白(空欄)= インターネット予約不可、黄 = 抽選申込受付中、緑 = 休館・保守

そのため、「●」の枠は**空きとして表示**し、点線の枠(☎)で、ネット予約できる枠(○)と区別します。枠の下に「ネット予約の受付外。電話や窓口でお申し込みください」と、電話番号のボタン(タップで発信)を出します。
- 生駒市は、直近の約10日間が「●」です。奈良市は、週末の直近や、サン・アクティブ奈良などが「●」です。
- 設定は `config/courts.json` の `offlineMarks`、`contacts`、`fallbackContact`。生駒市の7施設には、生駒市の公式ページ掲載の個別の番号を入れています(TAC井出山は、プールの番号ではなく、テニスコートの管理事務所の番号)。奈良市は施設ごとに窓口が違うため、施設ごとに登録しています(青山・鴻ノ池は個別の番号、柏木=南部生涯スポーツセンター、黒谷=西部生涯スポーツセンター、西部・南部・富雄・富雄南は個別の番号)。**佐保山と平城第一・第二は、担当課(スポーツ振興課)の番号で代用し、「施設自身の番号は未確認」と表示します。** 青山コートの番号は、青山コート自身にだけ使います。 二名・京西公民館、サン・アクティブ奈良、都祁生涯スポーツセンター(予約の問い合わせ先: 都祁行政センター地域振興課)も登録済みで、奈良市の全施設に連絡先があります。
- **電話番号は、検索結果で公式ページ掲載を確認したものです(私が公式ページを直接開いたわけではありません)。変更されていることがあります。** 間違いに気づいたら `config/courts.json` を直してください。

### 空き枠のコピー・共有
各コートの行に「コピー」(共有機能のある端末では、「共有」も)があります。押すと、次のような文になります。LINEやメモに貼って、一緒にテニスをする人に送れます。
```
【テニスコートの空き】
11/21(土) 奈良市柏木コート コートB
9:00〜12:00 / 13:00〜17:00
予約サイト: https://…
```
ネット予約の受付外(☎)の枠は、そう分かる印と、電話番号が入ります。

### データの大きさ(スマホ向け)
画面が読むデータは `data2.json` です(約170KB)。コート名を一覧に1回だけ持ち、連続する枠(9-10、10-11 …)を1つにまとめた形式で、従来の `data.json`(約1.9MB)より、約91%小さくなっています(`src/courts/compact.ts`)。まとめても、空いている時間帯は同じです(テストと、実データの全組み合わせで確認)。
- `data.json`(従来の形式)は、キャッシュに残った古い画面が読むために、しばらく残しています。新しい画面は読みません。しばらくしたら、削除できます。
- 今日の、すでに終わった時間の枠は、表示しません(日本時間のいまの時刻で判定。範囲全体が終わった枠だけを隠します)。

### 更新ボタン
画面の上に、2つのボタンがあります。
- **↻ 最新を読み込む**: 公開サイトの最新データを、画面に読み込み直します(すぐ使えます)。
- **⟳ 空き状況を取得し直す**: 各サイトから、空き状況を取得し直します(約5〜10分)。**中継役(Cloudflare Worker)の設置が必要**です。合言葉が必要で、連続の実行は受け付けません。設置の手順は `worker/README.md`、コードは `worker/src/` にあります(`npm run worker:build` で、貼り付け用の `worker/worker.js` を作ります)。

### 公式サイトへの遷移(絞り込み)
コート名・時間をタップすると、公式の予約サイトが新しいタブで開きます。
- **奈良市・生駒市**: 公式の検索フォームに、**選んだ日付と目的コード(硬式=035、軟式=036。コートごとに、出た検索のほうを使う)を入れて送信**するので、その日のテニスの検索結果が最初から表示されます(「日付を選ぶ→テニスを選ぶ→検索」の操作が、不要になります)。個別のコートだけには絞りません。
- **奈良スーパーアプリ**: 予約画面が受け付けるURLの指定は、施設と建物のIDなど(`facilitiesId`、`buildingId`)だけで、日付・設備の指定はありません(画面のプログラムで確認)。建物の予約画面までです。
- 木津川市: 公式サイトの入口です。

### 空きがない理由の区別(正確さのため)
「空きなし」だけでは、利用者に誤解を与えるので、施設ごと・日ごとに次の状態を区別して表示します(`src/courts/status.ts`)。
- **空きなし**: 枠はあるが、すべて予約済み。
- **休館・利用不可**: 休館・保守・主催事業・受付対象外・休館日など。
- **まだ空きが公開されていません**: 奈良スーパーアプリに、その日の枠が出ていない日(公開される範囲は、施設によって違います)。
- 実データでの確認(公式の画面と一致): 大和郡山市総合公園の 11/22(日)の「空きなし」、奈良市南部生涯スポーツセンター・まほろば健康パーク・明日香のオムニコートの 11/21(土)の空き。

### 木津川市(自動取得なし)
京都府の予約システムは自動アクセスを制限しているため、自動取得はしません(防御の回避もしません)。
- `config/courts.json` の `type: "link"` で、画面に「公式サイトで空きを確認」のカードを出します。`entryUrl` は普段開く空き状況ページに差し替えてください。
- 自分のブラウザで見た空き情報を、アプリに取り込む入口があります。アプリURLの `#import=<base64>` に次の JSON を載せて開くと、この端末の localStorage にだけ保存されます(サーバには送られません)。
  ```json
  {"source":"import","importedAt":"2026-11-06T07:20:00Z","slots":[{"date":"2026-11-14","site":"木津川市","facility":"木津川台公園","court":"テニスコートA","start":9,"end":12}]}
  ```
- 受け取った JSON は、型・範囲を検証してから使います。24時間以上前の取り込みは「古い可能性」と表示します。
- **ブックマークレット**で、公式の「施設別空き状況照会」画面から JSON を作って渡せます。
  - `npm run bookmarklet` で `public/bookmarklet.html`(登録用ページ)を生成します。`APP_URL` 環境変数で、アプリの公開URLを指定できます(既定 `https://saikoro86-boop.github.io/-/`)。
  - 解析は `src/courts/kizugawa.ts`(保存した実画面を使った `tests/kizugawa.test.ts` あり)。公式画面の `<img alt="空いています">` だけを空きとして読みます。
  - 画面に表示されている期間(7日間/31日間)だけが取り込めます。サイトへの追加アクセスはしません。
